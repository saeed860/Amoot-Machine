# ارزیابی امکان‌پذیری استخراج خودکار صفحات Cat Parts — 2026-11-25

## نتیجه اجرایی

**وضعیت: فعلاً قابل اتکا نیست؛ استخراج 839 صفحه‌ای با Playwright در GitHub Actions نباید مسیر اصلی داده‌سازی باشد.** اسکریپت به‌عنوان ابزار کمکی و آزمایشی قابل نگهداری است، اما پیش از استفاده تولیدی باید هم لایه انتقال شبکه و هم parser بازطراحی و با چند صفحه واقعی آزمون شود.

## شواهد فنی

1. اجرای قبلی روی سه شناسه اول (000-5242, 000-5251, 000-5252) هر سه با ERR_HTTP2_PROTOCOL_ERROR و بدون HTTP status شکست خورد. قطع‌کننده بعد از سه خطای متوالی batch را متوقف کرد؛ بنابراین هیچ SQL ناقصی ساخته نشد.
2. اصلاح بعدی Chromium را با --disable-http2 --disable-quic اجرا می‌کند و پس از خطای navigation صفحه را می‌سازد. اما این به‌تنهایی تضمین نمی‌کند مسیر HTTP/2 در لایه شبکه یا پراکسی runner حذف شده باشد.
3. اجرای اصلاح‌شده بعدی لغو شد و اجرای تازه‌تر هنوز نتیجه موفق/قابل ارزیابی نداده بود. بنابراین ادعای رفع خطای شبکه ممکن نیست.
4. parser فعلی با متن واقعی صفحه هم‌خوانی کامل ندارد. صفحه رسمی 500-0483 مشخصات را به شکل سطرهای جداگانه Material: و سپس مقدار در خط بعدی نشان می‌دهد؛ درحالی‌که regex اسکریپت انتظار Key (unit): value در یک خط را دارد. در نتیجه احتمالاً بخش عمده مشخصات استخراج نمی‌شود.
5. parser سازگاری مدل‌ها تمام توکن‌های بزرگ‌نویسی‌شده بخش را با regex عمومی جمع می‌کند؛ عنوان گروه‌هایی مانند GENERATOR، MATERIAL HANDLER و مقادیر متنی می‌توانند به‌اشتباه مدل ثبت شوند. این داده برای فیتمنت قطعه کافی نیست.
6. متن قابل مشاهده صفحه محصول شامل گروه‌های مدل و مدل‌های متعدد در یک رشته است؛ استخراج مطمئن باید مرز هر گروه، نام مدل، نام محصول، شناسه قطعه و وضعیت Factory Fit را جداگانه نگه دارد.
7. صفحه رسمی Cat می‌گوید انتخاب قطعه درست به serial/PIN و گاهی build number وابسته است؛ فهرست مدل‌های عمومی صفحه محصول به‌تنهایی تضمین فیتمنت یک دستگاه خاص نیست.

## تصمیم فنی

- عدم اجرای دسته‌های 100تایی روی 839 شناسه با parser فعلی.
- پیش از بازگشت به Playwright، یک POC محدود 5 تا 10 قطعه‌ای باید روی runner انجام شود و برای هر قطعه HTTP status، عنوان، شرح، حداقل یک مشخصه، مرز گروه مدل و تعداد مدل‌های معتبر با خروجی صفحه مقایسه شود.
- اگر POC شبکه‌ای با HTTP/1.1 هم پایدار نشد، مسیر Playwright کنار گذاشته شود؛ scraping مستقیم HTML/endpoint فقط پس از شناسایی endpoint عمومی و مجاز و آزمون نرخ درخواست بررسی شود.
- داده‌های PDFهای رسمی Cat Parts Reference Guide مسیر قابل اتکاتری برای کشف part number و fitment در سطح مدل/serial prefix هستند. باید منبع، عنوان راهنما، مدل، prefix، بازه سرویس و شرح دقیق برای هر ردیف ذخیره شود.
- صفحات محصول رسمی Cat برای تأیید ثانویه شرح و مشخصات و تصاویر استفاده شوند؛ قیمت حساب مشتری از صفحات عمومی استخراج یا حدس زده نشود.
- منابع فروشندگان/مارکت‌پلیس‌ها فقط به‌عنوان lead جداگانه نگهداری شوند، نه CAT OEM تأییدشده.
